`RelayerVault` is the public-side custody contract for the Morphex confidential bridge. It accepts public ERC-20 deposits, records withdrawal requests registered by the confidential token bridge, and lets the relayer pay them out in batches. If the relayer stalls, users can bypass it after a time-locked escape hatch.

## Overview

```solidity
import {AccessControl} from "@openzeppelin/contracts/access/AccessControl.sol";
import {ReentrancyGuard} from "@openzeppelin/contracts/utils/ReentrancyGuard.sol";
import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import {SafeERC20} from "@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol";

contract RelayerVault is ReentrancyGuard, AccessControl { ... }
```

Inherits `ReentrancyGuard` (OZ) for cross-function reentrancy protection and `AccessControl` for role gating.

## Constructor

```solidity
constructor(address admin, address initialRelayer, uint256 escapeHatchDelay_)
```

<ParamField path="admin" type="address">
  Receives `DEFAULT_ADMIN_ROLE`. Rotates relayer signers.
</ParamField>

<ParamField path="initialRelayer" type="address">
  Initial holder of `RELAYER_ROLE`. Signs batched payouts.
</ParamField>

<ParamField path="escapeHatchDelay_" type="uint256">
  Seconds a user must wait after a request before they can self-serve via `claimEscapedWithdrawal`. Must be greater than zero.
</ParamField>

Reverts on zero addresses or zero delay.

## Access Control

| Surface | Guard |
| --- | --- |
| `setRelayer`, `setRelayerSigner` | `onlyRole(DEFAULT_ADMIN_ROLE)` |
| `batchWithdraw` | `onlyRole(RELAYER_ROLE)` |
| `deposit`, `registerWithdrawalRequest`, `registerWithdrawalRequestTo`, `claimEscapedWithdrawal` | Public |

```solidity
bytes32 public constant RELAYER_ROLE = keccak256("RELAYER_ROLE");
```

<Note>
  The constructor grants the admin role to a single address for local testing. Production deployments should use a multisig-controlled admin.
</Note>

## State

```solidity
address public relayerSigner;
uint256 public immutable ESCAPE_HATCH_DELAY;
uint256 public nextRequestId;

struct WithdrawalRequest {
    address user;
    address recipient;
    address token;
    uint256 amount;
    uint256 requestedAt;
    bool fulfilled;
    bool escaped;
}

struct Payout {
    address recipient;
    address token;
    uint256 amount;
}

mapping(uint256 => WithdrawalRequest) public withdrawalRequests;
```

`nextRequestId` is a monotonic counter; the first request has id `1`.

## Administration

### setRelayer

```solidity
function setRelayer(address relayer) external onlyRole(DEFAULT_ADMIN_ROLE);
```

Rotates `RELAYER_ROLE` to a new signer. Revokes the previous holder and updates `relayerSigner`. Reverts on the zero address.

### setRelayerSigner

```solidity
function setRelayerSigner(address relayer) external onlyRole(DEFAULT_ADMIN_ROLE);
```

Alias of `setRelayer` used by local tests. Production should prefer a multisig-admin-controlled rotation flow.

## Deposits

### deposit

```solidity
function deposit(address token, uint256 amount) external nonReentrant;
```

Moves public ERC-20 tokens into the vault. Amounts and tokens are deliberately plaintext. Emits `Deposited(msg.sender, token, amount, block.timestamp)`.

The off-chain relayer watches `Deposited` and calls `MorphexToken.relayerMint` after confirmation.

## Withdrawals

### registerWithdrawalRequest

```solidity
function registerWithdrawalRequest(address user, address token, uint256 amount)
    external nonReentrant returns (uint256 requestId);
```

Records a user's intent to withdraw public funds to their own address. Called by `MorphexToken.relayerBurnRequest`.

### registerWithdrawalRequestTo

```solidity
function registerWithdrawalRequestTo(address user, address recipient, address token, uint256 amount)
    external nonReentrant returns (uint256 requestId);
```

Same as above but records a different `recipient`. Called by `MorphexToken.relayerBurnRequestTo`.

Both variants require non-zero `user`, `recipient`, `token`, and non-zero `amount`. Emit `WithdrawalRequested(user, requestId, token, recipient, amount, requestedAt)`.

### batchWithdraw

```solidity
function batchWithdraw(Payout[] calldata payouts, uint256[] calldata requestIds)
    external nonReentrant onlyRole(RELAYER_ROLE);
```

Pays out a batch of withdrawals in a single transaction. For each entry:

- Requires non-zero `recipient`, `token`, and `amount`.
- If `requestIds[i] != 0`, looks up the stored request and enforces that `recipient`, `token`, and `amount` match exactly. Marks the request `fulfilled = true`.

Transfers with `SafeERC20.safeTransfer` and emits `Withdrawn(recipient, token, amount, block.timestamp)` per payout.

<Note>
  Amount and recipient matching means the relayer cannot redirect funds to a different address or send a different amount than the user requested.
</Note>

### claimEscapedWithdrawal

```solidity
function claimEscapedWithdrawal(uint256 requestId) external nonReentrant;
```

User-callable trustless fallback. Requires:

- Request exists
- Caller is the original `user`
- Not already fulfilled
- `block.timestamp >= request.requestedAt + ESCAPE_HATCH_DELAY`

Marks the request `fulfilled = true` and `escaped = true`, then pays the recipient. Emits `EscapeHatchClaimed` and `Withdrawn`.

## Views

### reserves

```solidity
function reserves(address token) external view returns (uint256);
```

Returns the vault's public ERC-20 balance for a token. Used by off-chain tooling as a solvency signal.

### getWithdrawalRequest

```solidity
function getWithdrawalRequest(uint256 requestId)
    external view returns (
        address user, address recipient, address token,
        uint256 amount, uint256 requestedAt, bool fulfilled, bool escaped
    );
```

Returns the full request record. Useful for wallets to check whether a burn request has been paid out.
